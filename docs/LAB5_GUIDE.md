# Лабораторная №5: что изменилось

## Главная идея

Раньше Vite отдавал пустой HTML, а браузер запускал React и запрашивал данные. Теперь сначала работает сервер Next.js: проверяет сессию, получает данные из Java и формирует HTML. Затем React в браузере подключает обработчики событий — это hydration.

Java остаётся единственным backend с бизнес-логикой и базой. Next.js не подключается к PostgreSQL, не проверяет пароль и не назначает роли. Его сервер нужен для SSR, маршрутов, cookie и запросов к Java.

## Путь запроса страницы

1. Браузер открывает `/students/12`, автоматически передавая HttpOnly-cookie.
2. `src/proxy.js` (middleware в терминологии задания) обращается к Java `/api/users/me` с Bearer JWT. Если access истёк — запрашивает Java `/api/auth/refresh`, записывает новые cookie и передаёт их текущему SSR-запросу.
3. Без сессии происходит redirect на `/login?next=...`. При недоступном backend показывается отдельная страница, токены из-за сетевой ошибки не удаляются.
4. `app/(protected)/layout.jsx` получает пользователя через `requireUser` и передаёт его Context и меню. `React.cache` объединяет одинаковые вызовы requireUser внутри одного серверного рендеринга; это не постоянный кеш авторизации.
5. `app/(protected)/students/[id]/page.jsx` читает `id`, запрашивает Java через `loadStudents`, при 404 вызывает `notFound()`.
6. React-компонент карточки получает готовый объект студента. Его содержимое уже есть в HTML. В браузере подключаются ссылки, Context и синхронизация.

В этой реализации основное содержимое страницы не спрятано за streaming loading boundary: карточка должна читаться и без JavaScript. Загрузка отображается при браузерных запросах, отправке форм и переходе через ссылки меню (`useLinkStatus`).

## Путь изменения студента

1. `views/StudentFormPage.jsx` проверяет поля и вызывает `studentsApi.create` или `update`.
2. `api/client.js` отправляет JSON на тот же origin, например `/api/requests/12`. JWT в JS больше нет: браузер передаёт cookie сам.
3. Proxy проверяет сессию, а route handler `app/api/[...path]/route.js` разрешённый путь и Origin. Другой сайт не может выполнить cookie-authenticated изменение без совпадающего Origin.
4. Route handler читает access-cookie и отправляет JSON в Java с заголовком Authorization: Bearer. Java окончательно проверяет роль и поля, выполняет SQL.
5. Только после успешного ответа Java Next.js вызывает `revalidateTag("students", { expire: 0 })`.
6. Браузер получает результат, отправляет BroadcastChannel-сообщение и переходит на карточку. Другая вкладка списка вызывает reload RxJS; другая карточка — `router.refresh()`.

## Что означает кеш

В `server/data.js` используется стандартный Next.js fetch cache: `cache: "force-cache"`, `next: { revalidate: 60, tags: ["students"] }`. Повторный одинаковый GET может получить данные из кеша. Authorization входит в ключ запроса, поэтому разные токены не используют один и тот же ключ. Кеш профиля и паролей отключён.

Кеш не определяет права доступа. Перед чтением выполняется живая проверка Java. После успешной записи общий тег инвалидирует и списки с разными фильтрами, и карточки. Это проще и надёжнее для маленькой учебной базы, чем вычислять, какие именно списки затронуты.

Таймер revalidate — не push-уведомление и не обещание обновления экрана ровно через 60 секунд. Изменение через наш интерфейс обновляет кеш сразу; внешнее изменение будет обнаружено при последующих чтениях и перевалидации. Для нескольких экземпляров Next.js нужен согласованный внешний кеш; текущий Compose запускает один frontend.

## Какие файлы читать по порядку

| Файл/папка | Зачем читать |
|---|---|
| `src/app/layout.jsx` | HTML-документ, язык, общие стили и metadata |
| `src/app/(protected)/layout.jsx` | Общая оболочка защищённых страниц и SSR-пользователь |
| `src/proxy.js` | Middleware: текущая сессия, refresh, redirects, роль администратора |
| `src/server/backend.js` | Серверные запросы к Java и ограничение времени ожидания |
| `src/server/cookies.js` | HttpOnly-cookie, время жизни, удаление при выходе |
| `src/server/security.js` | CSRF Origin, разрешённые API-пути, безопасный redirect |
| `src/server/data.js` | Проверка пользователя, серверная загрузка и кеш студентов |
| `src/app/api/[...path]/route.js` | BFF: cookie → Bearer, Java API → ответ браузеру, сброс кеша |
| `src/app/(protected)/students/` | Страницы списка, карточки, создания и редактирования |
| `src/app/error.jsx`, `not-found.jsx` | Обработка ошибки рендеринга и отсутствующей страницы |
| `src/views/` | React-экраны: формы, события, локальные состояния |
| `src/auth/AuthContext.jsx` | Пользователь с SSR, обновление профиля и logout |
| `src/api/client.js` | Браузерный fetch без хранения JWT в JS |
| `src/api/studentEvents.js` | Твоя синхронизация вкладок через BroadcastChannel |
| `src/components/StudentSync.jsx` | Обновление серверной карточки при сообщении вкладки |
| `src/components/NavigationLink.jsx` | Клиентский переход и индикатор ожидания |
| `src/hooks/useStudents.js`, `src/reactive/studentsStream.js` | Прежние RxJS-фильтры, отмена запросов и обновление списка |
| `src/utils/studentQuery.js` | Общие исходные параметры для SSR и браузера |
| `next.config.mjs`, `Dockerfile` | Production standalone-сервер |

`views` раньше называлась `pages`. Папка `pages` зарезервирована Next.js под другой механизм маршрутизации; компоненты экранов перемещены, чтобы Next не создавал из них лишние URL.

Удалены Vite entry points `main.jsx`, `App.jsx`, `index.html`, `vite.config.js`, старый frontend nginx.conf, `ProtectedRoute.jsx` и sessionStorage-модуль `session.js`: их обязанности перешли к app-router, proxy и cookie.

## Как показать преподавателю

1. Запустить Docker, открыть приватное окно и зайти напрямую на `/students`: должно перенаправить на вход.
2. Зарегистрировать пользователя: роль USER, нет кнопок изменений. Прямой `/students/new` ведёт на недостаточные права, API-запись даёт 403.
3. В другом профиле браузера войти администратором. Показать фильтры, сортировку, пагинацию, профиль и выпадающий список общежитий.
4. Открыть две вкладки списка/карточки. Создать, изменить и удалить студента; показать обновление другой вкладки.
5. В DevTools → Application → Cookies показать HttpOnly access/refresh. В sessionStorage приложение JWT больше не сохраняет.
6. Открыть исходный HTML карточки или отключить JavaScript и обновить: ФИО и данные уже отображаются благодаря SSR. Формы без JS интерактивно работать не обязаны.
7. Открыть несуществующий URL и несуществующий ID — 404. Проверить неправильный пароль и серверную валидацию.
8. Показать server/data.js и успешную мутацию в route.js: где кешируется GET и где инвалидируется тег.
9. Запустить `node scripts/verify-lab5.mjs` из корня — автоматическая проверка с временной записью.

## Почему есть "use client", если нужен SSR

Эта директива разрешает hooks, обработчики событий и браузерные API. Она сама по себе не означает, что HTML компонента не создаётся на сервере. Серверная page загружает данные и передаёт сериализуемые props интерактивному компоненту; он участвует в SSR и затем гидратируется.

Необязательно переводить каждую таблицу и форму в серверный компонент. Важно, чтобы защищённые данные действительно загружались на сервере, а браузерные API не вызывались во время серверного рендеринга. BroadcastChannel и window используются в effects/обработчиках, а не на верхнем уровне модуля.
