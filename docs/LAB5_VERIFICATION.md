# Проверка лабораторной №5

Дата: 15 ноября 2026. Ветка: `API_part2`.

## Выполнено

- Production-сборка Next.js 16.4.6 локально и внутри Docker.
- `npm.cmd run lint`: без замечаний.
- `npm.cmd test`: 11 успешных тестов. Проверяются cookie transport, 401/403/204, ошибки валидации, AbortError, Origin CSRF, разрешённые API-пути, безопасные перенаправления, отмена устаревших запросов RxJS, debounce, фильтры и формы.
- Интеграционный `scripts/verify-lab5.mjs`: проверка на настоящих Java/PostgreSQL, временный студент удаляется в `finally`.
- Проверены redirect гостя, 401 API, CSRF 403, HttpOnly-cookie без JWT в теле login-ответа, текущая роль, CRUD, инвалидация уже прогретого кеша списка и карточки, восстановление сессии через refresh-cookie, 404, logout.
- Браузер Microsoft Edge (Playwright): вход через форму, создание/изменение/удаление через интерфейс, обновление списка и карточки в другой вкладке.
- Регистрация через форму: роль USER, отсутствуют кнопки записи, прямое открытие формы ведёт на недостаточные права, POST API возвращает 403. Временный аккаунт удалён после проверки.
- Карточка студента видна в браузере с полностью отключённым JavaScript.
- Мобильная ширина 390 px: нет горизонтального переполнения; оформление проверено также на 1440 px.
- В проверенных сценариях не было ошибок страницы и hydration mismatch.

Backend и его данные сохранялись. Проверки изменяли только собственные временные записи. Имя Compose-проекта осталось прежним для сохранения существующего volume.

## Что проверить самостоятельно перед защитой

1. `docker compose ps`: три сервиса работают, PostgreSQL healthy.
2. Открывать http://localhost:8080 (или адрес из APP_ORIGIN).
3. Показать поиск, фильтры, сортировку и переключение страниц на своих данных.
4. Показать SSR, HttpOnly-cookie, proxy и revalidateTag по сценарию из LAB5_GUIDE.md.
5. Помнить: синхронизация вкладок действует в пределах одного origin; внешние клиенты не получают push-уведомления. Refresh-токены пока не отзываются в таблице сессий.
